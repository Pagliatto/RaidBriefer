# 스토리 챕터 데이터

챕터마다 파일 하나 (예: tour.json).

- 단계 목록: 공식 위키 Objectives 순서와 같음 (`en` = 위키 원문)
- 한글 단계 이름·팁: 위키 가이드를 우리가 번역·요약 (EFT Library 표현은 용어 참고만)
- 사진: 공식 위키 이미지 링크 (출처 `source`)
- 출처: Escape from Tarkov Wiki (https://escapefromtarkov.fandom.com), CC BY-NC-SA 3.0
  → 이 폴더의 내용도 같은 조건(출처 표시, 비상업, 동일 조건 공유)으로만 쓴다.

## 점검

```
.venv\Scripts\python.exe -X utf8 tools\story_check.py
```

위키 목표 목록과 순서·개수 비교, 맵 구분값, 단계 id 중복, 선택 표시, 맵 표시 빠짐, 갈림길(엔딩별 길) 구조를 검사한다.
위키가 바뀌었거나 챕터 데이터를 고친 뒤에 돌려서 "문제 0개"인지 확인한다.

## 갈림길 (The Ticket 등)

- `sections` 안에 `{"choice": {"id", "title", "question", "options": [{"id","label","desc"}]}}` 항목을 넣으면 그 자리에서 선택지를 고른다.
- 구간에 `"when": {"갈림길id": "선택지id"}` (또는 선택지 목록) 을 달면 그 길을 골랐을 때만 보인다.
- 선택은 `user_data/progress.json` 의 story 에 `"챕터id@갈림길id": "선택지id"` 로 저장된다.

## 조건 더 쓰기

- 조건 키 종류: `"갈림길id"`(이 챕터), `"챕터id@갈림길id"`(다른 챕터), `"done:챕터id"`(챕터 완료, true/false), `"quest:id1,id2"`(퀘스트 완료, 게임 로그)
- `when`: 전부 맞아야 보임 / `when_any`: `[조건묶음, …]` 중 하나라도 맞으면 보임 (예: 생존자 길 = 제안 거절 또는 구원자 막힘)
- 단계에 `"manual": true`: 미리 알 수 없는 조건 → 연쇄 체크에서 빼고 "해당될 때만" 따로 체크
- `{"notice": true, "title", "tip", "when"}`: 단계 없는 안내 카드 (예: "구원자 길이 끝났어요")
- 갈림길 선택지에 `"blocked_when"`, `"blocked_note"`: 조건이 맞으면 ⛔ 막힘 표시

## 준비물(prep)의 퀘스트 아이템 표시

- `"kind": "제출"` 준비물은 서버가 이름(영어·한글)으로 아이템 id를 찾아 아이콘을 붙인다 (`app/story.py`).
- **퀘스트 아이템**(진행하며 그 자리에서 줍는 물건)은 홈 "뭘 모아 올까?"와 지도 "먹을 것"에서 뺀다.
  - tarkov.dev 퀘스트 아이템 목록(questItems)에 있으면 자동으로 `quest_item` 표시
  - 목록에 없는 고유 물건은 직접 `"quest_item": true` 를 적는다
    (예: 보예보다의 녹음기, AMG-10 유압유, 죽은 연구원의 오디오 테이프, Falling Skies 장갑 케이스, The Ticket 위험 화물 케이스)
  - **퀘스트 아이템은 인레이드(fir)가 아니다.** 인레이드 표시는 필드에서 주운 물건에만 붙는다.
    퀘스트 아이템은 임무 아이템 창에서 NPC와 주고받는 물건 → 서버가 `fir` 을 false 로 바꿔서 보낸다 (사용자 설명, 2026-11-17)
- 같은 이름의 아이템 여러 개는 한 줄에 실제 이름 + `count` 로 적는다 (예: C-1 구역의 하드 드라이브 ×3). `(1)(2)(3)` 처럼 이름을 바꾸면 아이템을 못 찾는다.
